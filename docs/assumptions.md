# Working assumptions

Unverified facts the design currently rests on. Each lists what was checked and the fallback if it proves false. Check these first when hardware and credentials are available.

| # | Assumption | Evidence so far | If false |
|---|---|---|---|
| A1 | Annotation items created through the Zotero web API (with the user's own key) appear in Zotero and stay editable. | Zotero's dataserver accepts the six annotation types with no third-party gate (source read); Zotero desktop syncs annotations through the same API. One 2026 forum report of failure. | The plugin writes annotations into the local Zotero database instead; they appear only while Zotero is running (ADR 0004 fallback). |
| A2 | The tablet loads v6 pages written by rmscene, including an extra "Zotero" layer, and keeps them when the user writes on the page. | Offline spike: rmscene wrote a page with two layers (a stroke on "Layer 1"; a stroke and text highlight on "Zotero"), read it back intact, and rmc rendered it. Not tried on a tablet. | Two-way sync narrows to tablet → Zotero; Zotero annotations reach the tablet only baked into the PDF. |
| A3 | rmfakecloud accepts a second sync client (the service) alongside the tablet, and the tablet picks up the service's changes. | **Server side verified** against rmfakecloud v0.0.32 in Docker (`tests/test_rmfakecloud_live.py`): device registration, generation-checked commits, blob/index formats, websocket notifications, and rmfakecloud's own UI parsing the documents. The tablet picking the changes up is still unverified. | Fall back to rmfakecloud's upload route for new documents; page writes would need an rmfakecloud change. |
| A4 | The tablet's software version is supported by rmfakecloud (tested up to 3.27.1). | The user's existing setup syncs today. | Pin the tablet's version; do not update the tablet until checked. |
| A5 | The reMarkable 2 EPUB typography options are: fonts Noto Sans, Noto Sans UI, EB Garamond, Noto Mono, Noto Serif; text scale 0.7/0.8/1/1.2/1.5/2; line height 100/150/200; margins 50/125/200; alignment default/justify/left. | Code comments in rmapi-js (reverse-engineered). | Adjust the option list after reading a real document's `.content` file. |
| A6 | The reMarkable 2 page is 1404×1872 px at 226 DPI (about 157.8×210.4 mm), and PDF points map to device pixels at 226/72. | rmapi-js `devices.ts` and rmapi's annotation exporter. | Measure from a synced PDF's page metadata. |
| A7 | Zotero WebDAV storage is `zotero/<ITEMKEY>.zip` plus `zotero/<ITEMKEY>.prop` (`<properties version="1"><mtime>…</mtime><hash>…</hash></properties>`, mtime in ms). | Zotero `webdav.js` source. | — |
| A8 | The tablet's native **Archive** feature (software 3.10+, a Connect feature: archived files turn grey with a cloud icon and are re-downloaded on tap) works with rmfakecloud, and the archived state can be set from the cloud side. | reMarkable 3.10 blog post describes the feature; nothing confirms rmfakecloud support or that the flag can be set by another sync client. | Build our own Placeholder documents, which in turn need A9. |
| A9 | Opening a document on the tablet updates its `lastOpened` metadata and syncs soon after. | Field exists (rmapi-js `raw.ts`); no evidence either way about sync timing. | Placeholders are retrieved by a different gesture, e.g. starring (`pinned`) them. |
| A10 | Pages inserted into a PDF on the tablet are identifiable, with their position relative to the original PDF pages recoverable from the document's `.content` (`cPages.pages[]` with `idx`/`redir`/`deleted`). | Field names exist in rmapi-js; their meaning is marked unknown there. | Inspect a real document with an inserted page and derive the mapping. |
| A11 | The tablet accepts documents uploaded with a service-generated page list (`cPages` with ids, `idx`, `redir`), so Zotero annotations can be drawn before the tablet first opens a document. | Format taken from rmapi's reader; the tablet normally creates this list itself. | Upload without a page list, and draw Zotero annotations only after the tablet has opened the document once. |
| A12 | Pages edited by the service (tombstoned items, appended items under the service's own author id, an extra layer) merge cleanly with the tablet's CRDT. | rmscene round-trips; the service only writes pages the tablet hasn't changed since it last read them. | Restrict service writes to the Zotero layer of pages with no concurrent edits (already the case) and investigate. |
| A13 | Zotero's renaming template is stored in the `attachmentRenameTemplate` preference. | Zotero source naming; not checked in a running Zotero. | The plugin falls back to the service's default template. |
| A14 | Zotero desktop accepts a PDF the service changed on WebDAV (note pages inserted) once the attachment's `md5`/`mtime` are updated through the API, and re-downloads it. | Zotero's sync docs allow editing md5/mtime for WebDAV libraries. | Keep tablet note pages only on the tablet and in a separate attachment. |
| A15 | The plugin loads in Zotero 7/8 (column, item pane section, settings pane, menu). | Type-checked; client contract-tested against the real service API. Running Zotero here was not permitted, so it has not been loaded in Zotero yet. | Fix whatever the Zotero error console reports on first load. |
